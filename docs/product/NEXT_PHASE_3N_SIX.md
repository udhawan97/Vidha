# Phase 3N content-free service-worker identity

**Status:** Six bounded source slices are implemented locally; exact-commit CI acceptance remains required. This phase lets the application identify one waiting service worker before accepting an Update Handoff and one controlling service worker after return. It is not cache or asset integrity, a real cross-build upgrade rehearsal, bad-service-worker recovery or rollback, state migration, persistence, deployment, or release authority.

Phase 3N closes the next fail-open browser gap after Phase 3M. The application could compare its own outgoing and returning identities but did not know which build the waiting or controlling service worker reported. A prompt could therefore describe a new build without binding the handoff to one expected worker identity.

## Gate after Phase 3N

Exact-commit local and CI checks must pass, including the existing Phase 3B disposable PostgreSQL, WebAuthn, backup, scheduler, and rootless-import rehearsals plus the Phase 3C–3M browser and document boundaries. Passing proves only that an update is offered after a distinct waiting worker self-reports one validated target identity and that a returning disposable WebKit page can compare the expected application and controlling-worker identities. It does not inspect cached responses or asset bytes; prove an actual old-build-to-new-build waiting-worker upgrade; recover, replace, or roll back a bad service worker; preserve or migrate session state; prove native Safari, Firefox, or Chromium support; authorize real identities or content; or enable Standard Mode, Sealed Mode, providers, Guardian Attestations, Veto Window, Delivery Hold, Automatic Fallback, Release, deployment, a tag, or a GitHub release. Every checkbox in sections 1–11 of `docs/release/V1_RELEASE_GATES.md` remains evidence-gated.
