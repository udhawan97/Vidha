# Phase 3P rejected update-candidate continuity

**Status:** Six bounded source slices are implemented locally; exact-commit CI acceptance remains required. This phase proves that one separately compiled target with an incomplete precache is rejected before it can wait or control the page, keeps the current synthetic rehearsal available, and does not prevent a later intact target from reaching the existing Update Handoff. It is not arbitrary cache or asset-byte integrity, recovery or rollback after a bad worker controls the page, state migration, persistence, native Safari or supported-browser qualification, deployment, or release authority.

Phase 3P closes the next negative-path gap after Phase 3O. The positive gate could move a complete target from waiting to controlling, but it did not prove what happened when installation discovered a missing required application-shell response. It also exposed a retry gap: after one installer became redundant, a later healthy worker reached `installed` without the application restoring its update offer.

## Gate after Phase 3P

Exact-commit local and CI checks must pass, including the existing Phase 3B disposable PostgreSQL, WebAuthn, backup, scheduler, and rootless-import rehearsals plus the Phase 3C–3O browser and document boundaries. Passing proves only that one deliberately incomplete precache is rejected before waiting or control, the still-open source rehearsal and controller remain available, and a later intact target can reach the existing content-free Update Handoff in desktop and mobile WebKit. It does not inspect arbitrary cached responses or asset bytes; cover syntax-invalid, malicious, partially functional, activated, or controlling bad workers; recover, replace, unregister, or roll back a bad worker; preserve state across navigation; prove native Safari, Firefox, Chromium, installed-app, offline-update, multi-origin, or supported-browser behavior; authorize real identities or content; or enable Standard Mode, Sealed Mode, providers, Guardian Attestations, Veto Window, Delivery Hold, Automatic Fallback, Release, deployment, a tag, or a GitHub release. Every checkbox in sections 1–11 of `docs/release/V1_RELEASE_GATES.md` remains evidence-gated.
