# Phase 3O cross-build Update Handoff rehearsal

**Status:** Six bounded source slices are implemented locally; exact-commit CI acceptance remains required. This phase exercises one real old-build to waiting-new-build service-worker update on disposable loopback production builds. It is not cache or asset-byte integrity, bad-service-worker recovery or rollback, state migration, persistence, native Safari or supported-browser qualification, deployment, or release authority.

Phase 3O closes the next evidence gap after Phase 3N. The application could validate a distinct waiting-worker identity and compare a returning application with its controller, but no test served two separate production builds through one origin and completed the real browser lifecycle. WebKit also exposed a fail-open seam: the target worker could activate and control the page without the update helper reloading the still-mounted source application.

## Gate after Phase 3O

Exact-commit local and CI checks must pass, including the existing Phase 3B disposable PostgreSQL, WebAuthn, backup, scheduler, and rootless-import rehearsals plus the Phase 3C–3N browser and document boundaries. Passing proves only that two separate disposable production builds can form a real waiting-worker transition on one loopback origin, the target worker can take control, the application requests a guarded reload on that browser event, and the returning target application and controller report the expected content-free identities in desktop and mobile WebKit. It does not inspect every cache response or asset byte; exercise a rejected, corrupt, or unusable target; recover, replace, or roll back a bad service worker; preserve or migrate session state; prove native Safari, Firefox, Chromium, installed-app, offline-update, multi-origin, or supported-browser behavior; authorize real identities or content; or enable Standard Mode, Sealed Mode, providers, Guardian Attestations, Veto Window, Delivery Hold, Automatic Fallback, Release, deployment, a tag, or a GitHub release. Every checkbox in sections 1–11 of `docs/release/V1_RELEASE_GATES.md` remains evidence-gated.
