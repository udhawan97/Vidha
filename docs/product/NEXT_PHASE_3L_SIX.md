# Phase 3L bounded update handoff safety

**Status:** Six bounded source slices are implemented locally; exact-commit CI acceptance remains required. This phase restores the Owner's local update decision when an accepted service-worker Update Handoff does not replace the current page in time or the previous page returns. It is not build-activation proof, cache inspection, bad-service-worker recovery or rollback, state migration, persistence, deployment, or release authority.

Phase 3L closes the next fail-open browser gap after Phase 3K. The confirmed update path disabled ordinary changed-work reload protection before calling the service-worker updater and restored it only after rejection. If that promise remained unsettled, or resolved without replacing the page, the dialog stayed busy and reload protection remained bypassed indefinitely. A page restored from browser history retained the same accepted-handoff state.

| 2     | Bounded still-live recovery     | Ten seconds after acceptance, a still-mounted page invalidates the attempt, exits its busy state, and restores the Owner's decision and changed-work reload protection | Deterministic fake-time tests cover an updater promise that resolves without navigation. ## Gate after Phase 3L

Exact-commit local and CI checks must pass, including the existing Phase 3B disposable PostgreSQL, WebAuthn, backup, scheduler, and rootless-import rehearsals plus the Phase 3C–3K browser and document boundaries. Passing proves only that a current synthetic page restores its local update decision and changed-work reload guard after a bounded still-live or browser-history-returned Update Handoff. It does not identify or activate a build; inspect, repair, replace, or roll back a service worker or cache; preserve or migrate session state; prove native Safari or another supported browser; authorize real identities or content; or enable Standard Mode, Sealed Mode, providers, Guardian Attestations, Veto Window, Delivery Hold, Automatic Fallback, Release, deployment, a tag, or a GitHub release. Every checkbox in sections 1–11 of `docs/release/V1_RELEASE_GATES.md` remains evidence-gated.
