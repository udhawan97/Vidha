Slice 1 uses only a run-sentinel-owned PostgreSQL database, run-unique content-free job/audit rows, a run-unique digest-pinned Compose fixture, and a tmpfs database root. Its migration and claim probes terminate identity-checked PostgreSQL backends, distinguish pre-commit rollback from post-commit lost acknowledgement, and retry with checksum/idempotency and fencing checks. Its worker-partition fixture uses a five-second client query-read timeout so a severed half-open socket reaches the bounded recovery path; that fixture value is not a production latency policy. The gate drops only its sentinel-owned rehearsal database, deletes only its generated capacity rows, removes its Compose project, restarts PostgreSQL without the application schema, and tears it down again. A passing exact-commit gate proves this bounded disposable behavior; it is not failover, high availability, general outage recovery, a production capacity claim, or persistent-volume evidence.

Slice 2 rewraps every selected metadata data key and writes one immutable rotation report in the same PostgreSQL transaction. Its lost-ack replay returns the committed report; conflicting reuse fails closed. The backup gate runs PostgreSQL 18 `pg_dump` and `pg_restore` from the digest-pinned image, excludes live runtime mode from the archive, wraps the custom archive behind the injected key-provider contract, signs two generations, advances an external file inventory only after artifact persistence, rejects a truncated archive and prior-generation rollback, restores through a dedicated non-superuser role, inserts `restore_safe` before any application adapter starts, verifies portable snapshots and migration checksums, proves the read-only inspection role cannot promote, then requires one immutable invariant digest for explicit promotion. Retention rehearsal can retire only an exact non-current generation. This is still a disposable bounded archive held in memory during encryption, not streaming backup software, external KMS custody, a durable-volume recovery result, RPO/RTO evidence, or a Standard Mode claim.

Slice 3 adds an opt-in runtime route that is rejected unless the API binds to `127.0.0.1` and the configured public origin is an exact `http://localhost:<port>` origin. The disposable flow creates only a synthetic Owner Credential, uses browser WebAuthn APIs against the existing ceremony coordinator, hashes the Owner ID into a standards-bounded user handle, issues only an opaque digest-backed `__Host-` session cookie, rotates it atomically, derives a session-bound CSRF token server-side, and revokes or expires authority through the canonical identity coordinator. POST routes require exact Host and Origin, JSON, bounded bodies, and same-origin fetch metadata when present; GET cannot mutate identity state. The CI gate uses a Chromium CDP virtual authenticator for the full registration/authentication/replay/rotation/revocation path and uses Firefox and WebKit only for the transport and security-header boundary. That is not real-authenticator, Safari, supported-browser, identity-proofing, public-origin, or production-session evidence.
