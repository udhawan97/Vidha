# Phase 3H multi-tab rehearsal safety

**Status:** Six bounded source slices are implemented locally; exact-commit CI acceptance remains required. This phase detects separate synthetic browser rehearsals and holds destructive local clearing while another tab reports changed work or an unsettled Owner action. It is not shared state, persistence, recovery, a cross-device lock, deployment, or release authority.

Phase 3H closes the next user-visible continuity gap after Phase 3G. Reload and service-worker updates were explicit inside one tab, but a second tab could look like the same rehearsal while actually holding a separate in-memory Plan, Editable Documents, imports, Attachments, Document Versions, review state, and local events. This phase makes that divergence visible without copying content between tabs or broadening the contingency state machine beyond Concern.

| ----- | ------------------------------ | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 1     | Content-free tab presence      | Same-origin tabs announce an ephemeral protocol version, per-tab identity, changed-work flag, and Owner-action flag through `BroadcastChannel`                                        | Messages contain no Plan, contact, Envelope, Editable Document, Attachment, filename, Recipient, or event data. Stop before shared state, persistence, cross-device discovery, analytics, or audit claims                                                         |
| 2     | Conservative peer-work signal  | Accepted session work and unsettled Owner actions are visible to peer tabs; malformed, foreign-protocol, and self messages are ignored                                                | The signal says only that work exists. It is not a canonical digest, content revision, server lock, merge base, or proof that every abrupt browser/process failure was observed                                                                                   |
| 3     | Honest divergence notice       | Every detected peer produces a non-dismissible status explaining that each tab is a separate rehearsal and that no content is copied or merged                                        | Component and multi-page WebKit checks cover clean peers and changed peers. Stop before claiming identical wording or lifecycle behavior in supported Safari, Firefox, or Chromium                                                                                |
| 4     | Destructive update hold        | A waiting service-worker build cannot update this tab while another tab reports changed work or an Owner action in progress                                                           | The update card names the other-tab condition and remains non-destructive. WebKit evidence is not native Safari acceptance, and `BroadcastChannel` absence remains an honest unsupported detection boundary |

## Gate after Phase 3H

Exact-commit local and CI checks must pass, including the existing Phase 3B disposable PostgreSQL, WebAuthn, backup, scheduler, and rootless-import rehearsals plus the Phase 3C–3G browser and document boundaries. Passing proves only a bounded content-free warning and two destructive holds between same-origin synthetic tabs at that commit. It does not synchronize, preserve, migrate, encrypt, merge, recover, or durably delete rehearsal state; prove installed or supported-browser behavior; authorize real identities or content; or enable Standard Mode, Sealed Mode, providers, Guardian Attestations, Veto Window, Delivery Hold, Automatic Fallback, Release, deployment, a tag, or a GitHub release. Every checkbox in sections 1–11 of `docs/release/V1_RELEASE_GATES.md` remains evidence-gated.
