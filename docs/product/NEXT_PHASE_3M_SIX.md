# Phase 3M content-free update receipt

**Status:** Six bounded source slices are implemented locally; exact-commit CI acceptance remains required. This phase gives a returning tab one content-free receipt that compares the application build before and after an accepted Update Handoff. It is not service-worker activation proof, cache inspection, update integrity, bad-service-worker recovery or rollback, state migration, persistence, deployment, or release authority.

Phase 3M closes the next fail-open browser gap after Phase 3L. A successful reload cleared the synthetic rehearsal, but the returning page exposed no identity for the application build it was running and no bounded account of the requested handoff. An Owner could therefore see a fresh rehearsal without knowing whether the page changed builds or merely reloaded the same build.

| Order | Bounded slice                      | Implemented outcome                                                                                                                                                                      | Evidence and stop condition                                                                                                                                                                                                   |
| ----- | ---------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 1     | Exact application build identity   | The build receives a validated, non-secret identity from `VIDHA_BUILD_ID` or the exact GitHub Actions SHA, with an explicit local-development fallback, and displays its bounded label   | JSON-safe build injection and a strict 1–80 character allowlist fail closed. Stop before signing, provenance attestation, artifact identity, deployment identity, or a version/release claim                                  |
| 2     | Content-free outgoing record       | Immediately before update activation, the tab records only a versioned protocol and its outgoing application build identity in `sessionStorage`                                          | Pure tests reject malformed, invalid, and content-bearing records. No Plan, contact, Envelope, Editable Document, Attachment, filename, Recipient, event, review state, or loss counts enter storage                          |
| 3     | Receipt-required handoff           | If the browser cannot record the bounded outgoing identity, the update does not start and the current rehearsal remains available                                                        | Component tests force unavailable storage and preserve the existing safe update decision. Stop before claiming `sessionStorage` is durable, encrypted, cross-tab, cross-device, server-authoritative, or a recovery mechanism |
| 4     | Returning-page classification      | A returning page compares the outgoing identity with its current build and reports either a changed application build or an explicitly unverified same-build return                      | The comparison proves only that this page's injected build identity changed. It does not prove the service worker, every cache entry, asset graph, server, or installed app is healthy or current                             |
| 5     | One-time accessible acknowledgment | The update surface announces the result, names the previous-session loss, keeps the current build visible, and consumes the tab-scoped record after the page reads it                    | Unit, component, and responsive WebKit tests cover the changed-build receipt and accessible boundary copy. Stop before telemetry, history, analytics, persistence, or download/update completion evidence                     |
| 6     | Failure and stale-path cleanup     | Rejected, timed-out, and browser-history-returned handoffs clear their outgoing record while retaining Phase 3L's attempt fencing, focus restoration, and changed-work reload protection | Exact-commit formatting, lint, type, build, documentation, accessibility, and full WebKit regression checks remain mandatory. WebKit is not native Safari, and the v1 PWA/browser gate remains fully unchecked                |

## Gate after Phase 3M

Exact-commit local and CI checks must pass, including the existing Phase 3B disposable PostgreSQL, WebAuthn, backup, scheduler, and rootless-import rehearsals plus the Phase 3C–3L browser and document boundaries. Passing proves only that an accepted update request leaves a content-free outgoing application-build identity and that a returning synthetic page distinguishes a changed injected build identity from an unverified same-build return. It does not prove service-worker activation, cache or asset integrity, a real waiting-worker upgrade, state preservation or migration, bad-service-worker recovery or rollback, native Safari or another supported browser, real identities or content, Standard Mode, Sealed Mode, providers, Guardian Attestations, Veto Window, Delivery Hold, Automatic Fallback, Release, deployment, a tag, or a GitHub release. Every checkbox in sections 1–11 of `docs/release/V1_RELEASE_GATES.md` remains evidence-gated.
