# Phase 3I file-review interruption safety

**Status:** Six bounded source slices are implemented locally; exact-commit CI acceptance remains required. This phase coordinates synthetic browser file review with Draft rehearsal, reload, update, and same-origin tab warnings. It is not upload, malware scanning, durable quarantine, persistence, encryption, shared state, deployment, or release authority.

Phase 3I closes the next fail-open browser gap after Phase 3H and the expanded Envelope review flow. File reads, fixture inspection, and import approval can settle asynchronously after the Owner leaves the Envelope workspace. Until now, the Overview and update surfaces could not distinguish that unsettled work from an idle tab, so a Draft review could omit a pending file decision and a waiting build could interrupt preparation without naming it.

## Gate after Phase 3I

Exact-commit local and CI checks must pass, including the existing Phase 3B disposable PostgreSQL, WebAuthn, backup, scheduler, and rootless-import rehearsals plus the Phase 3C–3H browser and document boundaries. Passing proves only that this synthetic client does not review or arm a Draft around an unsettled local file decision and does not begin an update during file preparation or approval. It does not upload, scan, preserve, encrypt, synchronize, recover, or durably delete files; prove installed or supported-browser behavior; authorize real identities or content; or enable Standard Mode, Sealed Mode, providers, Guardian Attestations, Veto Window, Delivery Hold, Automatic Fallback, Release, deployment, a tag, or a GitHub release. Every checkbox in sections 1–11 of `docs/release/V1_RELEASE_GATES.md` remains evidence-gated.
