# Use WebAuthn and revocable server sessions for Owner identity

Vidha will act as its own WebAuthn relying party behind a replaceable verification adapter. An Owner may bind multiple passkey-backed Owner Credentials. Successful authentication generates an opaque, expiring server session; the caller cannot choose its secret, only a digest is persisted, global digest collision fails closed, and the server remains authoritative for expiry and revocation. Identity mutations use an expected security revision and semantic idempotency digest so lost-response retries do not repeat authority or notices and concurrent stale commands cannot overwrite newer state. Ordinary mutations require an active session plus CSRF protection, while lifecycle-sensitive and identity-authority changes require a fresh assertion with verified user presence and user verification. Email or SMS control alone never authenticates a Check-in or lifecycle mutation.

Recovery, credential revocation, session revocation, and Verified Owner Channel changes remain explicit identity state transitions. The accepted recovery direction requires two independently stored and delivered proofs, a cooling-off period, content-free notice intents to existing Verified Owner Channels, credential replacement, and invalidation of prior sessions. A channel change requires fresh authentication, proof of the new channel, notice to old and new channels, an authenticated cancellation path, cooling-off, and session invalidation when it becomes authoritative. If independence and cancellation cannot be demonstrated for a real recovery design, recovery completion stays disabled.

This trades the convenience of hosted identity and contact-only recovery for self-hostability, phishing-resistant authentication, and immediate revocation. `packages/identity` is disposable contract evidence only: its injected proof verifier is not a WebAuthn server, identity-proofing system, browser-support result, real recovery factor, or production session store.
