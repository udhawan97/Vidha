# Isolate classification, malware scanning, and document conversion

The accepted untrusted-file target keeps exact bytes in quarantine, classifies them with a pinned `libmagic` process, scans the same digest through a pinned ClamAV `INSTREAM` process, and converts only an accepted scan proof in a fresh resource-bounded OCI job using a pinned Pandoc executable. Classification, scanner, and converter processes receive no Vidha database or provider credentials, runtime socket, writable host path, or general network access. Signature updating runs separately with restricted egress. Errors, timeouts, limit hits, stale evidence, type mismatch, encrypted or unsupported inputs, and unknown output nodes fail closed.

Every inspection proof binds the source digest and byte count, scanner and signature versions, start and completion times, verdict, and isolation profile. Conversion uses a positive reader and output-node allowlist, disables filters and external resource fetching, and treats converter output as untrusted until canonical validation. Unsupported originals remain Attachment candidates rather than being forced through editable conversion.

This accepts more operational work and GPL distribution review in exchange for a narrow, self-hostable process boundary. A scanner's clean verdict does not prove a file safe, and containerization does not prove isolation. Phase 3B adds source-hash-pinned file classification, digest-pinned ClamAV `INSTREAM`, pinned Pandoc sandbox-mode JSON conversion, an immutable signature-manifest identity, and a rootless Podman fixture with bounded output/time/resources, AST/link allowlists, read-only exact-input mounts, no network, cleanup, and an adversarial corpus. The updater fixture only materializes the database already embedded in the pinned image; it is not a production signature-update or restricted-egress service. No real upload, durable quarantine, general sandbox-support, or safe-file claim exists.
